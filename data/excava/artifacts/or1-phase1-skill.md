## Overhaul (GPT-4o-mini · mistral/mistral-small-latest)

**GOOD:** A skill element excels when it is *actionable*—users can immediately apply it to a real task without extra setup, like a one-click prompt template for summarizing research papers. It should also be *measurable*, with clear inputs, outputs, and success criteria (e.g., "reduces response time by 30%"). Good skills are *modular*, meaning they work independently or combine seamlessly with others, and they include *contextual cues* (e.g., "Use this for cold emails, not technical docs"). They’re also *transparent*—users can inspect or tweak the underlying logic (e.g., adjustable parameters) rather than treating it as a black box.

**MEDIOCRE:** A mediocre skill is vague or overly generic, like "improve writing quality" without specifying tone, audience, or constraints. It might require manual data prep (e.g., "clean your dataset first") or rely on external tools the user lacks. Mediocre skills often lack edge cases—failing silently or producing inconsistent results when inputs vary slightly. They may also be *redundant*, duplicating functionality already covered by simpler tools (e.g., a 10-step "optimize LinkedIn profile" template when a 3-step one suffices).

**DISQUALIFIES:** An outright disqualifier is a skill that *harms* the user’s goals, such as one that generates plausible but false information ("hallucinates" sources) or introduces bias without disclosure (e.g., favoring certain demographics in hiring advice). Skills that violate ethical guidelines—like automating spam or bypassing security checks—are also disqualified. Finally, skills that *break the tool’s core functionality* (e.g., a prompt that crashes the AI hub) are non-starters.

**Observable signals:** Reviewers can check for *reproducibility* (does the skill work consistently across test cases?), *documentation* (are inputs/outputs defined?), and *user effort* (how many manual steps are required?). They can also measure *impact* via before/after comparisons (e.g., time saved, error reduction) and scan for *hidden dependencies* (e.g., "requires Python 3.11"). Skills with no test cases, vague metrics, or proprietary logic that can’t be audited raise red flags.
