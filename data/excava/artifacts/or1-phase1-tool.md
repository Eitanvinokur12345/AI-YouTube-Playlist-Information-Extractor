## Overhaul (Mistral · mistral/mistral-small-latest)

**GOOD** looks like a tool with a clear, singular purpose—one that solves a specific problem so well it feels inevitable once you see it. It has a crisp interface, minimal friction, and documentation that anticipates your next question before you ask it. The signals are obvious: a focused README, a single binary or one-line install, and a demo that works on the first try. It’s opinionated but not dogmatic, offering sensible defaults while staying flexible enough for edge cases. Users don’t need to read a manual; they just *get it*.

**MEDIOCRE** looks like a tool that tries to do too much, leaving users to cobble together workflows from scattered docs and half-baked examples. It might have a bloated interface, confusing flags, or a README that reads like a stream-of-consciousness brain dump. The signals are subtle but consistent: inconsistent naming, outdated screenshots, or a demo that fails unless you tweak hidden settings. It’s not *bad*—just forgettable, the kind of tool you use once and then abandon for something cleaner.

**DISQUALIFIES** an item outright if it’s broken by design—no clear purpose, no working demo, or a license that restricts use to the point of absurdity. The signals are undeniable: a tool that crashes on trivial inputs, a repo with zero commits in a year, or a "tool" that’s just a wrapper for a paid API with no local alternative. If it requires a PhD to set up or a server farm to run, it’s not a tool—it’s a project masquerading as one.
